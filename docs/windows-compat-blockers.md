# Windows compatibility blockers

Review snapshot: 13 October 2026, branch `windows-compat`, HEAD `27b5f63`.

All items are fixed and checked off (13 October 2026): a fresh MinGW i686 build and the Linux build both compile cleanly, and the ABI-critical values (glibc FORTIFY prototypes, X11/Xlib layouts, PulseAudio state enums, MinGW `IP_ADAPTER_INFO`, `IP_ADDRESS_STRING`) were checked against the installed system headers. `GLHooks_RealGlProc`/`GLHooks_RealGluProc` in `glHooks.cpp` provide the cdecl passthroughs for the GL and the imported GLU symbols; the unbuffered `roxor_trace.log` writes are now gated behind `ROXOR_TRACE` (the `memoryManager.cpp` and `roxor.c` boot-trace sites, also unconditional, were gated with them). B28 and B29, found while field-testing Jurassic Park on Windows (the dump's stripped section headers hid the game's exported symbols from the input hooks; `glX`/`glut` imports were routed past the loader's bridges and 21 GL extension entry points were unfetchable before a context exists), were fixed the same day: symbol lookups now fall back to the loaded image's `.dynamic` table the way `dlsym` reads it, and the GL import routing/forwarders of `rtDump.c` give the game its missing entry points.

Scope: all three commits created after branching from `rawthrills` at `a7315b7` (`fdb4f21`, `101ca58`, `27b5f63`), plus the pending edits to `roxor.c` and `roxorIo.c`. Earlier inherited commits on `rawthrills` are outside this branch's changes. The ZIPs are build artifacts, not additional source changes.

The code builds, but the branch has multiple runtime blockers. P1 means a startup failure, memory corruption, or a major functional regression; P2 means a narrower functional problem. Findings below are source-level findings unless a reproduction is explicitly described.

- [x] **B01 [P1, committed] TLS allocation writes before its buffer and uses inconsistent DTV indices.** [tlsSupport.cpp:283](../src/loader/elfLoader/tlsSupport.cpp#L283). `dtv` is the allocation base, yet initialization writes `dtv[-1].counter`. The TCB subsequently stores `dtv + 1`, although module entries were populated relative to the unshifted pointer. Capacity, generation and module pointers consequently refer to different entries when `GetAddr` reads them. The resize path repeats the underflow with `nd[-1]`. An AddressSanitizer harness running the actual source with mocked Windows TLS/lock APIs reported a four-byte write eight bytes before the allocation at line 296. Keep a separate allocation base and consistently use `base + 1` as the logical DTV pointer during initialization and resizing. `EnsureThreadTls` runs for the main thread and every emulated pthread, even without a game TLS segment.

- [x] **B02 [P1, committed, also breaks Linux] Namco ES1 code protection subtracts the page address from a length.** [namcoEs1.c:738](../src/loader/namco/namcoEs1.c#L738). `makeCodeWritable(page, end)` computes `end - page`, but `patchCode`, `detour`, `windowAtOutputSize`, `redirectCall` and `setMovImmediate` pass the rounded byte length as the second argument. A 4096-byte request at page `0x08048000` becomes `0xf7fb9000` bytes on 32-bit. The actual helper failed with `ENOMEM` in a Linux harness. Dongle, self-check, camera and window patches are skipped. Either accept a length or pass `page + length` at every caller.

- [x] **B03 [P1, committed] Import hooks change a local array rather than the executable's GOT.** [importHook.c:27](../src/loader/common/importHook.c#L27). `slots[i]` is the address of a GOT entry. The original target must be read through `*slots[i]`, and the replacement must be written through it. The current assignment only changes the local array; the returned original is a data address. A harness invoking the actual function left a GOT value `0x12345678` unchanged after requesting `0x87654321`, and returned the wrong original. This prevents Namco SDL/dlsym/setsockopt and CSNEO dlopen hooks from being installed. [SymbolResolver::HookImport:631](../src/loader/elfLoader/symbolResolver.cpp#L631) does write the GOT, but also returns the slot address instead of its previous contents, so its original-function result needs the same correction.

- [x] **B04 [P1, committed] Namco alignment stubs target GOT data and are never installed.** [namcoEs1Align.c:63](../src/loader/namco/namcoEs1Align.c#L63). The stub receives `slots[i]` rather than `*slots[i]`, then `slots[i] = ...` updates only the temporary array. The log claims aligned imports, but the game retains unaligned calls. Fix both dereferences; otherwise Dead Heat's library alignment faults remain, and merely fixing the assignment would make the new stub execute GOT data.

- [x] **B05 [P1, committed] Raw Thrills rebinding installs address 1.** [rtDump.c:122](../src/loader/rawthrills/rtDump.c#L122). `rtOverride(name) || rtWrapper(name)` produces an integer boolean, not either function pointer. For non-GL imports with a replacement, such as `SDL_SetVideoMode` or `SDL_GL_SwapBuffers`, the GOT becomes `1`, and the next call faults. Preserve the first non-null pointer with an explicit fallback. The clean cross-build warns about this conversion.

- [x] **B06 [P1, committed and pending] Linux GL calls are rebound directly to Windows stdcall functions.** [rtDump.c:87](../src/loader/rawthrills/rtDump.c#L87), [rtDump.c:119](../src/loader/rawthrills/rtDump.c#L119), [roxor.c:229](../src/loader/roxor/roxor.c#L229). The ELF callers use cdecl, while 32-bit `opengl32.dll` GL functions use `APIENTRY`/stdcall. Both sides remove the arguments. The alignment trampoline preserves callee popping, so it does not adapt this convention: a 32-bit executable harness showed zero stack drift with a cdecl target and four bytes of drift with a one-argument stdcall target. Retain the existing cdecl `wrap_gl*` adapters and load GLAD after SDL creates a current context, or introduce explicit ABI adapters. The newly added [GLU fallback:2709](../src/loader/elfLoader/glHooks.cpp#L2709) has the same problem when returning raw `glu32.dll` functions. The WGL pointers in [rtFrame.c:65](../src/loader/rawthrills/rtFrame.c#L65) and [roxor.c:135](../src/loader/roxor/roxor.c#L135) also need `WINAPI` rather than plain C function-pointer types; current unoptimized code can mask that ABI error.

- [x] **B07 [P1, committed] FORTIFY bridge prototypes omit or reorder real arguments.** [libcBridge.cpp:1152](../src/loader/elfLoader/libcBridge.cpp#L1152), [rtBridge.cpp:115](../src/loader/elfLoader/rtBridge.cpp#L115). `__snprintf_chk` is `(dest, count, flag, destination_size, format, ...)`; the bridge omits `destination_size`, treating a small size such as 64 as the format pointer. `__sprintf_chk`, `__swprintf_chk`, `__vsnprintf_chk` and `__vsprintf_chk` have the same missing-size problem. `__strcpy_chk`, `__strcat_chk`, `__stpcpy_chk` and wide equivalents put the source before the destination-size argument, whereas these bridges reverse them. `__fread_chk` takes `(dest, destination_size, element_size, count, stream)`, unlike the current ordering. Match each public ABI before ignoring bounds checks. Local glibc headers confirm these prototypes.

- [x] **B08 [P1, committed] `environ` is registered one pointer level too shallow.** [libcBridge.cpp:91](../src/loader/elfLoader/libcBridge.cpp#L91). An ELF import of this data symbol expects the address of the `char **environ` variable. Registering its current value makes the caller dereference the array's first string pointer as though it were an environment vector. This can explain Tcl environment initialization failures. Register the address of an appropriate `char **` variable, consistently with the existing stdout/stderr data mappings.

- [x] **B09 [P1, committed] Cancellation bridges interpret integer modes as pointers.** [pthreadBridge.cpp:182](../src/loader/elfLoader/pthreadBridge.cpp#L182). Both pthread functions take `(int mode, int *oldmode)`, but the replacement accepts only `int *oldtype`. `pthread_setcancelstate(PTHREAD_CANCEL_DISABLE, ...)` and `pthread_setcanceltype(PTHREAD_CANCEL_ASYNCHRONOUS, ...)` pass `1`, and the bridge writes to address `1`. With mode zero, the real output pointer is ignored. Keep the correct two-argument signatures even for no-op implementations.

- [x] **B10 [P1, committed] Namco N2 rejects every normal function entry.** [namcoN2Hook.c:19](../src/loader/namco/namcoN2Hook.c#L19). Windows defines `STT_FUNC` as 13; ELF uses 2. The preprocessor confirms 13 is the active definition. The `epCallback` filter therefore skips the game's `adm*`/GL function slots. Use ELF's value 2; this is independent of host platform.

- [x] **B11 [P1, committed and pending] Windows file redirection handles only Teamplay.** [gamePath.c:26](../src/loader/common/gamePath.c#L26). All Raw Thrills, Namco and Roxor dispatches remain under `__linux__`. The new Windows fopen/open/access/stat/chdir bridges call this function, but receive the unmodified cabinet paths. Paths such as `/tux/.tuxracer-v1/options` and `/opt/arcade/exec/...` cannot reach the directories the corresponding Windows initializers prepare. Enable the families now compiled on Windows, while keeping Global VR behind its existing platform guard.

- [x] **B12 [P1, committed] `getaddrinfo` overwrites the caller's result pointer and adjacent memory.** [rtBridge.cpp:434](../src/loader/elfLoader/rtBridge.cpp#L434). POSIX, like Winsock, takes `struct addrinfo **result`. The bridge takes `struct addrinfo *` and clears an entire struct at that address. A harness using the actual bridge body and the real pointer-output allocation reproduced an AddressSanitizer overflow. On 32-bit Windows the caller provides a four-byte pointer slot, not an addrinfo object. Return a valid failure code and, if setting an output, clear only `*result`.

- [x] **B13 [P1, committed] The setjmp rewrite loses the saved instruction pointer.** [libcBridge.cpp:298](../src/loader/elfLoader/libcBridge.cpp#L298), [libcBridge.cpp:316](../src/loader/elfLoader/libcBridge.cpp#L316). The previous code saved post-return ESP and the return PC separately. The replacement stores EFLAGS and the pre-return ESP, relying on the old return address still occupying the stack. Normal calls after setjmp can overwrite that consumed return slot, so longjmp's `ret` can jump elsewhere. This also is not the documented six-word i386 glibc layout claimed by the comment. Preserve a stable return PC and restore the matching stack/register layout in both longjmp variants; distinguish any compiler-builtin format separately.

- [x] **B14 [P1, committed] New X11 bridges contain incompatible output layouts and signatures.** [x11Bridge.c:805](../src/loader/graphics/x11Bridge.c#L805), [x11Bridge.c:833](../src/loader/graphics/x11Bridge.c#L833), [x11Bridge.c:848](../src/loader/graphics/x11Bridge.c#L848). On i386 `XColor` is 12 bytes, but `XAllocColor` clears 24; `XSizeHints` is 72 bytes, but `XAllocSizeHints` allocates 48. Compile-time layout checks against Xlib confirmed both sizes. Real `XGetWMHints` takes two arguments and returns an allocated pointer; the bridge reads a nonexistent third argument and clears memory through it. `XGetPointerControl` similarly writes through two more output pointers than its actual API supplies. These must match the Linux ABI even when the display is simulated; use typed structs instead of guessed buffers.

- [x] **B15 [P1, committed] Linux resource structures are written with incorrect sizes.** [rtBridge.cpp:1168](../src/loader/elfLoader/rtBridge.cpp#L1168). `getrlimit` clears 16 bytes, but the ordinary i386 `struct rlimit` supplied by these 32-bit games is eight bytes; a `-m32` compile-time size check confirmed this. The `RtSysInfo` definition at [rtBridge.cpp:609](../src/loader/elfLoader/rtBridge.cpp#L609) is also larger than the Linux i386 object and puts fields at incorrect offsets, so its `memset(sizeof(*info))` overruns the caller's object. Define exact guest structures and separate 64-bit variants. The fixed 256/512-byte clears in the ogg/theora stubs should also be audited against their actual guest struct definitions before those entry points are used.

- [x] **B16 [P1, committed] The new ALSA periods setter is missing its first argument.** [alsa2sdl.c:481](../src/loader/audio/lindbergh/alsa2sdl/alsa2sdl.c#L481). `snd_pcm_hw_params_set_periods_near` takes `(pcm, params, value, direction)`, but the replacement takes only `(params, value, direction)`. It interprets the PCM handle as a params object and the params object as `unsigned int *`, writing the wrong object and leaving the requested periods unset. Include `snd_pcm_t *pcm`, as neighboring ALSA setters already do.

- [x] **B17 [P1, committed] Anonymous TLS relocations resolve to module zero.** [elfLoader.cpp:627](../src/loader/elfLoader/elfLoader.cpp#L627). For `R_386_TLS_DTPMOD32` with symbol index zero, the module is the current shared object. The new code looks up an empty symbol name and writes zero. A small i386 shared library with a static thread-local integer produced exactly this relocation. `GetAddr(0, ...)` then returns the TCB instead of the variable's TLS block. Use `m_TlsModid` for anonymous relocations and honor the appropriate symbol/addend rules for the other TLS relocation forms.

- [x] **B18 [P2, pending] Tcl evaluates native Windows path backslashes as escapes.** [roxor.c:106](../src/loader/roxor/roxor.c#L106). `_getcwd` returns backslashes, but the path is emitted inside a double-quoted Tcl string. Evaluating the generated `set data_dir "C:\games\tuxracer/data"` with Tcl removed the `\g` backslash and converted `\t` to a tab. Normalize separators and serialize the value safely for Tcl, including paths containing `$`, brackets or quotes. This becomes visible once the options replacement issue below is fixed.

- [x] **B19 [P1, Windows port gap exposed by pending code] The rewritten options file is never installed.** [roxor.c:118](../src/loader/roxor/roxor.c#L118). `path` necessarily already exists because it was opened for reading. The Windows CRT's `rename(tmp, path)` refuses to replace an existing destination, and the return value is ignored. Consequently the new Windows data path and fullscreen setting remain in `options.new`, while the game reads the old file. Use a Windows replacement operation and handle failures. This rename statement was inherited, but its platform assumption must be corrected for this new Windows execution path. [Microsoft's rename documentation](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/rename-wrename).

- [x] **B20 [P2, committed] Mouse input and the quit watch compare a thread ID with a process ID.** [desktopInput.c:137](../src/loader/common/desktopInput.c#L137), [desktopInput.c:163](../src/loader/common/desktopInput.c#L163). `GetWindowThreadProcessId` returns the thread ID and writes the process ID through its second argument. Comparing its return value to `GetCurrentProcessId()` normally rejects the game's own window. Mouse position/buttons stay zero and Esc/Alt+F4 from this watch do not quit. Compare the output PID. Mouse coordinates should also use the client rectangle, since the current window rectangle includes the title bar and borders.

- [x] **B21 [P2, committed] Letter-key aliases use the wrong Windows virtual-key codes.** [desktopInput.c:43](../src/loader/common/desktopInput.c#L43), [rtJamma.c:300](../src/loader/rawthrills/rtJamma.c#L300). Windows letter virtual keys are uppercase ASCII values. Lowercase `'i'`, `'u'`, `'z'`, etc. collide with unrelated numpad/function keys, so start/coin aliases and Z/X/C/V buttons do not follow their documented controls. For example lowercase `'p'` is the F1 virtual-key value. Use uppercase virtual-key constants and address physical-layout handling explicitly if needed.

- [x] **B22 [P2, committed] PulseAudio never reports a ready context and uses several wrong operation ABIs.** [alsa2sdl.c:597](../src/loader/audio/lindbergh/alsa2sdl/alsa2sdl.c#L597). `PA_CONTEXT_READY` is 4, while this implementation returns 1 (`CONNECTING`); a client waiting for ready never progresses. `PA_OPERATION_DONE` is 1, while the implementation returns 2 (`CANCELLED`). `pa_stream_connect_playback` also interprets device-name and buffer-attributes arguments as audio data and byte count, and `pa_stream_write` returns frames written rather than zero on success. Match public prototypes/states and make asynchronous operations/callbacks consistent with the claimed ready implementation.

- [x] **B23 [P2, committed] OpenAL path formatting overlaps its input and output.** [namcoN2Audio.c:78](../src/loader/namco/namcoN2Audio.c#L78). `snprintf(path, ..., "%s\\ll-deps\\openal32.dll", path)` has undefined behavior. It can discard the executable-directory prefix and fail to find the packaged DLL, leaving N2 silent. The clean cross-build emits `-Wrestrict`. Keep the directory and full filename in separate buffers.

- [x] **B24 [P2, committed] Windows adapter IPv4 addresses are copied as text bytes.** [namcoEs1Network.c:95](../src/loader/namco/namcoEs1Network.c#L95). `IP_ADAPTER_INFO` stores dotted-decimal strings. Copying their first four bytes into the address/mask yields ASCII numbers, e.g. `192.` becomes `49.57.50.46`, and the test for a loopback first octet 127 cannot work. Parse both strings to IPv4 octets before selecting/reporting the interface.

- [x] **B25 [P1, committed] Correct the argument order of `bcopy`.** [rtBridge.cpp:1404](../src/loader/elfLoader/rtBridge.cpp#L1404) reverses BSD's `(source, destination, count)` order, writing into the source. Preserve the guest API order and copy from source to destination; verify with separate buffers.

- [x] **B26 [P2, committed] Write double outputs in `sincos`.** [rtBridge.cpp:554](../src/loader/elfLoader/rtBridge.cpp#L554) writes floats to the double output objects required by `sincos`, leaving half of each object unchanged. Use `double *` outputs and keep the separate float implementation for `sincosf`.

- [x] **B27 [P1, committed] Fix `strerror_r` buffer bounds and return ABI.** [rtBridge.cpp:1458](../src/loader/elfLoader/rtBridge.cpp#L1458) starts copying at index 1 and can place the terminator at `buf[buflen]`. The GNU variant returns a string pointer, while the bridge returns an integer. Match the guest variant, copy from index zero, and terminate within the buffer; verify zero, one-byte, and truncated buffers.

- [x] **B28 [P1, fixed, found in Jurassic Park field testing] The input hooks cannot find the game's own symbols in dumps without section headers.** [rtIo.c:793](../src/loader/rawthrills/rtIo.c#L793). The first real-Windows run of Jurassic Park failed with "input hooks not installed": `rtSymbol`/`rtTrampoline` resolve `InputAddMap`/`GameInputMaps` through `FindExportedSymbol`, which reads the file's `.dynsym` *section*; cabinet dumps have no section headers at all (the envelope stripped them — the Cruis'n Blast, Walking Dead and Galaga dumps on hand have none, and the Big Buck one's section table points past the end of the file), so every lookup returns NULL. Linux does not hit this because the same lookup is `dlsym`, which reads `.dynamic`'s `DT_SYMTAB`/`DT_STRTAB` without any section headers. The fix reads that table from the loaded image (`PT_DYNAMIC` → `DT_SYMTAB`/`DT_STRTAB`, the relocated pointers) when the sections are absent or unreadable, counts entries through `.hash`'s nchain or, as in these GNU-hash-only dumps, is bounded by the string table, and matches names the way `dlsym` does (versioned `foo@GLIBC_2.0` matches `foo`); `rtInstallInput` now logs which symbol is missing. The walk was validated against a real section-less dump (a section-stripped Big Buck copy: its 563 entries all walk, `printf` is found and rejected as undefined, a defined entry is accepted). The real-Windows JP run still has to confirm it.

- [x] **B29 [P1, fixed, found in Jurassic Park field testing] GL/GLX/glut import resolution routes the wrong names and leaves extension entry points unfetchable before a context.** [rtDump.c:427](../src/loader/rawthrills/rtDump.c#L427). `resolveImport` sent *every* name starting with `gl` to `rtGlImport`, so `glX*` and `glut*` imports never reached the loader's own bridges in `graphicsBridge.cpp` (which implement them) and came back "not found". Separately, the 21 GL extension entry points in the JP import table (`glBlitFramebuffer`, `glTexImage3D`, `glGenerateMipmap`, …) are fetchable only through `wglGetProcAddress`, which answers nothing before a GL context exists; the import tables are rebuilt before the game creates one, so those GOT slots stayed 0 and the game's first call would fault. Route `glX`/`glut` to `bridgeResolveSymbol`, and for the extension names give the game cdecl forwarders that fetch the entry point on first call (the game then has a context) and no-op, logged once, if the ICD truly lacks it. Both builds pass; the real-Windows JP run has to confirm the imports resolve.

Validation: a fresh MinGW build in `/tmp/linuxloader-review-win32-build` completed successfully; the existing `build-linux` target also built successfully. Compiler warnings corroborated the import-slot assignments, boolean-to-pointer rebinding and overlapping OpenAL formatting. Focused harnesses reproduced the import-hook no-op, the TLS allocation underflow, the getaddrinfo overwrite, the Namco protection failure, and cdecl/stdcall stack drift. Tcl reproduced the path escaping failure. Linux guest structure sizes and TLS relocation shape were checked with the installed headers/compiler. Harnesses isolate these errors; they do not establish successful game execution on real Windows. The review did not change implementation files. Full game execution on real Windows remains to be validated after the blockers are fixed.

**Release cleanup:** The remaining diagnostics in `roxorIo.c`, `libcBridge.cpp` and `init.c` write `roxor_trace.log` unconditionally, unlike the `ROXOR_TRACE` guard on exception tracing. Gate them before shipping; I/O polling opens and closes the file repeatedly. The committed saved web pages, local development launch scripts and the two untracked ZIPs also deserve a packaging cleanup, but they are not counted as functional findings above.
